# Tested-ideas catalogue v3 (2026-11-08)

Catalogue v3 adds the 14 Swarm Collusion ideas (7 methods, each on the fixed-signal and reworded-signal testbeds) to the Tested-ideas catalogue. It is an additive import. Every idea, testbed and direction signal published in v2 is unchanged, byte for byte. The v2 planning snapshot stays at `/research/test-matrix-2026-10-31/catalogue-snapshot.json`.

## What was added

- 14 ideas and 2 testbeds (`swarm_collusion` v0.1 and `swarm_collusion_para` v0.2), copied verbatim from Alignment SynthCore `results/commons.json` at commit `e2274d1`. `import.json` records the commit, the export's SHA-256, a hash of each copied row, and the previous catalogue's hash.
- 2 direction signals, one per swarm testbed. They are not pooled with other testbeds.
- In the test registry (`/test-matrix.json`): one catalogue row per new idea, plus two pre-written follow-up designs per idea, 28 in total.

Harness verdicts: transcript monitor, exploit hunting and reviewer reputation beat the baseline on both versions. Dissent escalation beats it on v0.1 and fails its gate on v0.2. The channel-dependence and semantic-channel detectors fail their gates on both. The formal gate's mechanism holds, but it does not beat the baseline.

## Read the swarm rows with this caveat

On the test episodes the harness-tuned baseline scored 0.445, because a tuning tie selected a weak prompt. The best baseline configuration in hindsight scored 0.828. Each catalogue row with a benchmark therefore reports both comparisons. The hindsight comparison is exploratory, because it was chosen after seeing test results.

| Idea | vs hindsight-best baseline |
|---|---|
| Transcript monitor | +0.060 (p = 0.016); v0.2 +0.046 (p = 0.016) |
| Exploit hunting | +0.042 (p = 0.148); v0.2 +0.043 (p = 0.141), underpowered |
| Dissent escalation (v0.1) | +0.016 (p = 0.008) |
| Reviewer reputation | +0.009 (p = 0.008); v0.2 +0.010 (p = 0.008) |
| Formal gate | -0.223 (p = 0.031); v0.2 -0.221 (p = 0.031) |

These p-values are bootstrap screening statistics over a fixed set of cached episodes, not fresh generations.

## The 28 follow-up designs

All 28 are unregistered drafts. None has a result, none is queued, and their thresholds are planning choices that still need power checks on development episodes. They share the following rules:

- The baseline is chosen on development episodes from the full prompt grid, so the tie artifact cannot recur.
- The unit of analysis is a freshly generated episode shard.
- Development and confirmation episodes are disjoint.

The designs target the open weaknesses in the swarm results:

- **Fresh generations instead of resamples.** Transcript monitor replication, exploit-hunting power.
- **Adaptive red teams.** Monitor-aware colluders, e-process-aware colluders, signal rotation, unanimity-only attackers.
- **Cost and baseline fairness.** A token-matched baseline, an audit-budget sweep.
- **Attribution.** A signal-free collusion ablation, a direct colluder-recognition audit, a decomposition of why dissent escalation fell on v0.2.
- **Protocols the programme derived but did not register.** Block-and-audit for the formal gate, a spec defence against a colluding formalizer, alarm-triggered audit routing.

The full Swarm Collusion programme (report, figures, pre-registrations) is at [`/research/swarm-collusion/`](/research/swarm-collusion/README.md). Its exploratory protocol, e-process and conformity results do not change any catalogue verdict.
